# Generated asynchronous TypeScript ports — design

Status: implemented and verified within the coordinated workflow improvement.

## Interface

Add `mirrorecma-async-v1` as an explicit compiler target. Keep the synchronous
`mirrorecma-v1` emitter and its existing generated bytes unchanged. Both targets
consume the same verified lock, carry the same semantic digest/contract, and
use their own target-marked ownership manifest and output directory.

The async target emits model-specific typed inputs, observations, and port
methods, plus a binding whose `computer` is an `AsyncStateComputer`. Each action
accepts `ReplayContext` after its typed inputs (initializers without inputs take
only context); observations receive context too. Methods may return a value or
promise. The generated binding awaits the action, checks cancellation, awaits
the observation, validates/encodes it, then returns the state. Each step is
serialized and action coverage increments only after successful observation.

The port remains free of expected/previous model state. Failure, abort,
reentrancy, and invalid observations poison the binding. A callback that ignores
cancellation may still finish its own side effects, but the generated binding
must not proceed to observation/reporting afterward.

Register an async compiled binding under target `mirrorecma-async-v1` and local
contract `mirrors.async-state-computer/v1`. The existing server negotiation needs
no new wire fields: target lowering is client-local, while the server checks the
language-neutral semantic identity.

## Compiler integration and validation

Extend the CLI target allowlist, target dispatch, and ownership-manifest target
validation consistently. Manifest ownership stays explicit; generation/check
against one target must not silently accept another target's manifest.

Reuse existing semantic resolution, codecs, type lowering, and publication
rules. Parameterize rendering where possible rather than introducing a second
independent resolver. A dedicated async output fixture should compile against
the new client types, replay Counter using an awaited asynchronous port, and
reject cancellation/late observation. Existing synchronous golden output must
remain byte-identical. Negative compiler tests exercise target mismatch and
unsupported targets.

This target adds no claims of formal verification for generated JavaScript.
